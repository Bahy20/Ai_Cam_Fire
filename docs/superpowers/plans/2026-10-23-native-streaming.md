# Deploy native MiniCPM live streaming

User explicitly requested deployment of native streaming, authorizing a GPU upgrade if necessary. Execute inline; keep working through deployed verification.

Architecture: existing authenticated browser WSS -> CPU gateway -> one persistent authenticated GPU WSS. A dedicated native GPU endpoint owns one MiniCPM duplex session per connection and calls the pinned model's actual as_duplex/prepare/streaming_prefill/streaming_generate APIs, preserving KV context between chunks. Feed live frames without YOLO gating. Keep the existing recorded-upload analyzer separate to avoid sharing mutable stream state. Use bounded latest-frame buffering, strict source timestamps, one live session, ten-minute connection expiry, native sliding context window, and clear stream state on disconnect. Do not send backend credentials to the browser.

Native video-only mode: no audio capture or synthesis. The pinned wrapper unconditionally initializes speech synthesis in as_duplex even when generate_audio=False; narrowly suppress that unused TTS initialization while leaving native vision prefill, generation, decoder and KV cache unchanged. Verify this adaptation remotely before deployment, rather than loading unused speech dependencies/weights.
