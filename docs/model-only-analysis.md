# MiniCPM-only product path

The user authorized removing YOLO after its repeated false smoke proposals blocked the model's lighter classification. The production server now imports `VlmCoordinator` and `FrameReader`; it does not import the historical detector coordinator. The Modal CPU image omits YOLO weights, Ultralytics, CPU PyTorch, the old coordinator/priority/Scout files and the edge detector implementation. Historical experiments and the user's original training checkpoint are archived under `legacy/` (for example `legacy/detector/fire_seg.pt`), outside the deployed product.

The private frame reader validates JPEG/video bounds and measures existing pixel-quality statistics. It emits no detections. The exact usable quality-checked images are forwarded over the persistent native GPU WebSocket. Malformed native reports invalidate monitoring support, including its temporal interval. Reports from before a gap or invalid-response barrier cannot qualify a subsequent scene. A quiet/listening transport state cannot supply a negative observation.

Policy `minicpm-only-v5` derives current flame/smoke findings from strict frame-bound model enums. Three distinct reports spanning at least two seconds are required to allow negative-scene monitoring or reviewed-camera lighter monitoring (`EXPECTED_LIGHTER_CAMERAS`). A bounded eight-second support pool accommodates source timestamp jitter; the oldest supporting image must remain within ten seconds. Every intervening report must agree. Smoke, material burning, separate flame, uncertainty and occlusion prevent a lighter downgrade. A smoke/material/separate-flame hazard latches on two valid hazard reports within 20 seconds; invalid or uncertain reports, gaps and reconnects between them do not discard the first, while three consecutive clear reports dismiss a pending single report. If any pending report comes from a low-detail (blurry or grainy) frame, latching needs 3 reports, and a low-detail report stays pending for 40 seconds. A field a report marks present while its own description explicitly negates it (for example smoke `present` with "no smoke visible") counts as uncertain. Frames showing confident whole-view camera motion are skipped. A lighter or match flame at its tip with nothing else burning gets low priority (`monitor`) on every camera and for testers unless `EXPECTED_LIGHTER_CAMERAS` lists specific cameras; vapor from a visible vape is not reported as smoke. A single live smoke/material report shows `hazard_unconfirmed`, an upload that ends on an unconfirmed report is flagged for inspection (`hazard_unconfirmed_recording`), and the live model session resets its context after any hazard report so the confirming report is judged fresh. While latched, every newer hazard report refreshes the alert, so an operator review of older evidence is rejected. A latched hazard persists through loss of view and reconnect; an old YOLO-only incident cannot become model-confirmed evidence. Its current priority is restored after eight consecutive valid clear reports, each at most 15 seconds apart, with the latest one current, so slow model cadence cannot pin an old alert; gaps, invalid reports and non-clear reports, including non-clear reports rejected as stale or unusable, reset that streak. Incident history stays visible, and operator review resets the incident.

Recorded uploads make MiniCPM calls without detector triggers. Usable short clips receive inference, while insufficient temporal evidence remains unknown. Cause is still unverified; recognizing a lighter or burning material does not establish ignition causation. The browser displays visual-assessment findings and keeps missing/expired-report states visible.

Independent re-review found no remaining concrete blockers in scope. Fresh deployment results are recorded below after real public inference; these local checks are not claimed as cloud inference.
